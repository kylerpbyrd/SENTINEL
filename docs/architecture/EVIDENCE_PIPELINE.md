## Part 1: Evidence Object Model

### 1.1 Design Principles

- **Immutable** — Evidence objects are frozen once constructed. No analyzer may mutate another's evidence.
- **Serializable** — Must survive `structuredClone()`, cross-context message passing (content script → service worker → sandbox → popup → side panel), and JSON serialization for export.
- **Self-describing** — Any consumer (fusion engine, explanation generator, UI) can interpret an Evidence object without knowing which analyzer produced it.
- **Attributable** — Every field's origin is traceable. The system must know who set what, when, and under what conditions.
- **Privacy-aware** — The privacy classification of each evidence object governs where it can be transmitted and how it can be cached.

### 1.2 Canonical Evidence Interface

```typescript
/**
 * Immutable evidence object emitted by every analyzer plugin.
 * All timestamps are ISO 8601 UTC.
 * All hashes are SHA-256 hex-encoded unless otherwise noted.
 */
interface Evidence {
  // ============================================================================
  // 1. IDENTITY — Uniquely identifies this piece of evidence and its origin
  // ============================================================================

  /** UUID v7 (time-ordered). Generated by the pipeline, NOT the analyzer. */
  readonly evidence_id: string;

  /** Unique identifier of the analyzer that produced this evidence (e.g. "c2pa-verifier"). */
  readonly analyzer_id: string;

  /** Semantic version of the analyzer (e.g. "2.1.3"). Enables version-aware fusion and deprecation. */
  readonly analyzer_version: string;

  /** Classification of the evidence type for routing and weighting. */
  readonly evidence_class: EvidenceClass;

  // ============================================================================
  // 2. TIMESTAMP — When evidence was gathered
  // ============================================================================

  /** ISO 8601 UTC timestamp of evidence gathering completion. Timezone-agnostic. */
  readonly gathered_at: string;

  // ============================================================================
  // 3. ORIGIN — Which browser context or execution environment produced this
  // ============================================================================

  readonly origin: ExecutionContext;

  // ============================================================================
  // 4. CONTENT REFERENCE — What content this evidence is about
  // ============================================================================

  /** Uniquely identifies the content segment being analyzed.
   *  Format: "urn:sentinel:content:<content_hash>[:<fragment_id>]"
   *  Example: "urn:sentinel:content:sha256:abc123...:img-3"
   */
  readonly content_reference: ContentReference;

  // ============================================================================
  // 5. SIGNAL — What the analyzer detected (structured, not free-form)
  // ============================================================================

  readonly signal: Signal;

  // ============================================================================
  // 6. CONFIDENCE — Analyzer's self-assessed certainty
  // ============================================================================

  readonly confidence: Confidence;

  // ============================================================================
  // 7. RELIABILITY — Inherent reliability tier of this evidence type
  // ============================================================================

  readonly reliability_tier: ReliabilityTier;

  // ============================================================================
  // 8. WEIGHT — How much this evidence contributes to fusion
  // ============================================================================

  /**
   * Derived by the pipeline during CONFIRMATION ASSIGNMENT stage.
   * Set to null at emission. The pipeline computes weight from:
   *   weight = f(reliability_tier, confidence, analyzer_historical_calibration,
   *               independence_from_other_evidence)
   * Analyzers MUST NOT set this field.
   */
  readonly weight: number | null;

  // ============================================================================
  // 9. DEPENDENCIES — Which other evidence IDs this evidence depends on
  // ============================================================================

  /**
   * Evidence IDs that must exist and be valid for this evidence to be meaningful.
   * Example: Cross-modal consistency evidence depends on both image-forensics
   * evidence AND text-analysis evidence.
   * Empty array = no dependencies (this evidence stands alone).
   */
  readonly dependencies: string[];

  // ============================================================================
  // 10. RELATIONSHIPS — Semantic relationships to other evidence
  // ============================================================================

  readonly relationships: EvidenceRelationship[];

  // ============================================================================
  // 11. REPRODUCIBILITY — Would re-running produce the same result?
  // ============================================================================

  readonly reproducibility: Reproducibility;

  // ============================================================================
  // 12. EXPLAINABILITY — Human-readable explanation
  // ============================================================================

  readonly explanation: Explanation;

  // ============================================================================
  // 13. PRIVACY CLASSIFICATION — Governs transmission and caching
  // ============================================================================

  readonly privacy_classification: PrivacyClassification;

  // ============================================================================
  // 14. EXPIRATION — When this evidence becomes stale
  // ============================================================================

  readonly expiration: Expiration;

  // ============================================================================
  // 15. CACHEABILITY — Can this evidence be cached? For how long? Encryption?
  // ============================================================================

  readonly cacheability: Cacheability;

  // ============================================================================
  // 16. VERIFICATION STATE — Has this evidence been independently verified?
  // ============================================================================

  readonly verification_state: VerificationState;

  // ============================================================================
  // 17. BROWSER CONTEXT — Runtime environment capabilities
  // ============================================================================

  readonly runtime_context: RuntimeContext;

  // ============================================================================
  // 18. ERROR INFO — Structured error if evidence gathering failed
  // ============================================================================

  readonly error: EvidenceError | null;

  // ============================================================================
  // 19. METADATA — Extensible key-value for analyzer-specific detail
  // ============================================================================

  readonly metadata: Record<string, unknown>;
}
```

### 1.3 Supporting Type Definitions

```typescript
// ---------------------------------------------------------------------------
// 1. IDENTITY types
// ---------------------------------------------------------------------------

type EvidenceClass =
  | "PROVENANCE"       // Cryptographic or metadata-based origin verification (C2PA, EXIF, IPTC, XMP, hardware attestation)
  | "FORENSIC"         // Content-based analysis (ELA, noise patterns, frequency domain, AI fingerprints)
  | "WATERMARK"        // Embedded watermark detection (DALL-E, Midjourney, SD, Firefly, SynthID)
  | "STATISTICAL"      // Statistical/behavioral analysis (text burstiness, style consistency, repetition patterns)
  | "REPUTATION"       // Source/domain/publisher reputation (domain age, credibility, community signals)
  | "CROSS_MODAL"      // Cross-modal consistency (image-text mismatch, lip-sync, physics violations)
  | "REFERENCE"        // External reference lookups (fact-check database, reverse search, known AI hash)
  | "DERIVED"          // Computed from other evidence (agreement scores, coverage completeness)
  | "SYSTEM"           // Pipeline-internal evidence (timeout occurred, context unavailable)

// ---------------------------------------------------------------------------
// 3. ORIGIN types
// ---------------------------------------------------------------------------

type ExecutionContext =
  | "content_script"     // Has DOM access. Isolated from page JS. 50ms sync budget.
  | "service_worker"     // Orchestration. No DOM. 30s idle timeout, 5min max operation.
  | "sandbox"            // Sandboxed page. Relaxed CSP for WASM. Heavy compute.
  | "offscreen"          // Offscreen document. Chrome/Edge only. One at a time.
  | "popup"              // Extension popup. User-visible. Ephemeral (dismissed = terminated).
  | "side_panel"         // Chrome side panel. Persistent while open.
  | "cloud"              // Remote service. Requires network. Opt-in.

// ---------------------------------------------------------------------------
// 4. CONTENT REFERENCE types
// ---------------------------------------------------------------------------

interface ContentReference {
  /** Content hash (SHA-256 hex). Immutable content fingerprint. */
  readonly content_hash: string;

  /** Human-readable label for the content segment (e.g. "Article body", "Image #3"). */
  readonly label: string;

  /** MIME type of the content (e.g. "image/jpeg", "text/html", "video/mp4"). */
  readonly mime_type: string;

  /**
   * For compound content (web pages with multiple elements): which fragment
   * of the page this evidence is about. Null for standalone content.
   *
   * Scoped to the content_hash:
   *   - "body-text"  → the main article text
   *   - "img-3"      → the third image element
   *   - "video-1"    → the first video element
   *   - null         → the content as a whole
   */
  readonly fragment_id: string | null;

  /**
   * Semantic locator within the page structure. Used for UI anchoring
   * (e.g., highlighting the image this evidence is about).
   * Format: CSS selector path (most stable available) OR null if not applicable.
   */
  readonly dom_locator: string | null;

  /** Content URL at the time of analysis. May differ from current URL (SPA, redirects). */
  readonly source_url: string;

  /** Byte size of the content, if known. null for streaming/live content. */
  readonly byte_size: number | null;
}

// ---------------------------------------------------------------------------
// 5. SIGNAL types
// ---------------------------------------------------------------------------

interface Signal {
  /**
   * The signal type: what kind of thing was detected.
   * Enables fusion engine to route and weight signals without type-checking values.
   */
  readonly signal_type: SignalType;

  /**
   * The signal value: what was detected, in a structured form.
   * Interpretation depends on signal_type.
   *   - DISCRETE      → SignalDiscrete
   *   - CONTINUOUS    → SignalContinuous
   *   - BINARY        → SignalBinary
   *   - ABSENCE       → SignalAbsence
   *   - RICH          → SignalRich (arbitrary structured data, must include schema reference)
   */
  readonly signal_value: SignalValue;

  /**
   * Direction of the signal relative to authenticity.
   *   - AUTHENTIC    → evidence supports content being genuine
   *   - SYNTHETIC    → evidence supports content being AI-generated/manipulated
   *   - NEUTRAL      → evidence is informative but doesn't point either way
   *   - CONFLICT     → evidence itself is internally contradictory
   */
  readonly signal_direction: SignalDirection;
}

  // Cryptographic & provenance
  | "C2PA_MANIFEST_VALID"
  | "C2PA_MANIFEST_INVALID"
  | "C2PA_MANIFEST_ABSENT"
  | "HARDWARE_ATTESTATION"
  | "CRJSON_PROVENANCE"

  // Metadata
  | "EXIF_METADATA"
  | "IPTC_METADATA"
  | "XMP_METADATA"
  | "ICC_PROFILE"
  | "IPTC_DIGITAL_SOURCE_TYPE"

  // Image forensics
  | "ELA_ANALYSIS"
  | "NOISE_PATTERN"
  | "FREQUENCY_DOMAIN"
  | "JPEG_COMPRESSION_ARTIFACTS"
  | "AI_GENERATOR_FINGERPRINT"
  | "DOUBLE_COMPRESSION"

  // Watermark detection
  | "DALLE_WATERMARK"
  | "MIDJOURNEY_WATERMARK"
  | "FIREFLY_CREDENTIAL"
  | "SD_WATERMARK"
  | "SYNTHID_INDICATOR"

  // Text analysis
  | "TEXT_PERPLEXITY"
  | "TEXT_BURSTINESS"
  | "TEXT_STYLE_CONSISTENCY"
  | "TEXT_REPETITION_PATTERN"

  // Video/Audio
  | "FACE_MANIPULATION"
  | "VOCAL_CLONING"
  | "AUDIO_DEEPFAKE"
  | "VIDEO_PROVENANCE"
  | "VIDEO_METADATA"

  // Reference & Reputation
  | "DOMAIN_REPUTATION"
  | "KNOWN_AI_HASH_MATCH"
  | "FACT_CHECK_MATCH"
  | "REVERSE_SEARCH_RESULT"
  | "SOURCE_CREDIBILITY"

  // Cross-modal
  | "CROSS_MODAL_CONSISTENCY"
  | "IMAGE_TEXT_SEMANTIC_MISMATCH"
  | "MULTI_IMAGE_CONSISTENCY"
  | "TEMPORAL_COHERENCE"

  // Meta
  | "SIGNAL_AGREEMENT"
  | "SIGNAL_DISAGREEMENT"
  | "COVERAGE_COMPLETENESS"
  | "PAGE_STRUCTURE_CLASSIFICATION"
  | "CONTENT_VOLUME_METRICS"

  // System
  | "ANALYZER_UNAVAILABLE"
  | "CONTEXT_TIMEOUT"
  | "CORS_BLOCKED"
  | "SHADOW_DOM_BLOCKED"
  | "BROWSER_CAPABILITY_MISSING"
  | "OFFLINE_MODE"
  ;

type SignalValue =
  | SignalDiscrete
  | SignalContinuous
  | SignalBinary
  | SignalAbsence
  | SignalRich;

interface SignalDiscrete {
  readonly kind: "DISCRETE";
  /** Standardized category from a controlled vocabulary. */
  readonly category: string;
  /** Human-readable label for the category. */
  readonly label: string;
}

interface SignalContinuous {
  readonly kind: "CONTINUOUS";
  /** Floating-point score. Range must be documented in metadata. */
  readonly score: number;
  /** Lower bound of the meaningful score range (inclusive). */
  readonly min: number;
  /** Upper bound of the meaningful score range (inclusive). */
  readonly max: number;
  /** Which direction of this score indicates synthetic? -1 (lower = synthetic), 0 (absolute value matters), 1 (higher = synthetic). */
  readonly synthetic_direction: -1 | 0 | 1;
}

interface SignalBinary {
  readonly kind: "BINARY";
  /** The binary value. MUST NOT be used to represent "AI/Human" verdicts for text content (per TRUST_ENGINE_SPEC Section 4.1). */
  readonly value: boolean;
  /** What true means (e.g. "Watermark detected"). */
  readonly true_meaning: string;
  /** What false means (e.g. "No watermark detected"). */
  readonly false_meaning: string;
}

interface SignalAbsence {
  readonly kind: "ABSENCE";
  /** What was looked for but not found. */
  readonly sought: string;
  /** Why absence matters (context). MUST NOT imply negative signal for C2PA absence (per TRUST_ENGINE_SPEC Section 4.2). */
  readonly significance: string;
}

interface SignalRich {
  readonly kind: "RICH";
  /** Reference to a JSON Schema that describes the structure of `data`. */
  readonly schema_ref: string;
  /** Arbitrary structured data conforming to schema_ref. */
  readonly data: Record<string, unknown>;
  /** Summary string for display in quick-glance views. Max 140 chars. */
  readonly summary: string;
}

type SignalDirection = "AUTHENTIC" | "SYNTHETIC" | "NEUTRAL" | "CONFLICT";

// ---------------------------------------------------------------------------
// 6. CONFIDENCE type
// ---------------------------------------------------------------------------

/**
 * The analyzer's self-assessed certainty. Calibrated: confidence 0.95 MUST mean
 * the analyzer is correct ~95% of the time when emitting this confidence level,
 * measured against ground truth on the calibration dataset.
 */
interface Confidence {
  /** 0.0 (no confidence) to 1.0 (absolute certainty). */
  readonly score: number;

  /** The calibration set this confidence is relative to (e.g. "midjourney-v6-test-set"). */
  readonly calibration_set: string;

  /** Date the analyzer was last calibrated against ground truth (ISO 8601). */
  readonly last_calibrated: string;

  /**
   * Was this confidence value produced by the model's own calibration
   * (SELF_ASSESSED) or by an external calibration procedure (EXTERNALLY_CALIBRATED)?
   */
  readonly calibration_method: "SELF_ASSESSED" | "EXTERNALLY_CALIBRATED";

  /**
   * Uncertainty decomposition (optional but recommended):
   *   - aleatoric: inherent randomness in the data (can't be reduced)
   *   - epistemic: model/analyzer uncertainty (can be reduced with better models)
   * Both 0.0 to 1.0. Sum may exceed 1.0 (they're orthogonal dimensions).
   */
  readonly aleatoric_uncertainty: number | null;
  readonly epistemic_uncertainty: number | null;
}

// ---------------------------------------------------------------------------
// 7. RELIABILITY type
// ---------------------------------------------------------------------------

/**
 * Inherent reliability tier. Set by the ANALYZER based on evidence type,
 * NOT by the pipeline. The pipeline uses this for initial weight assignment.
 *
 * See TRUST_ENGINE_SPEC Section 3 for the tier hierarchy and rationale.
 */
type ReliabilityTier =
  | "GROUND_TRUTH"    // Tier 1: Cryptographic/hardware guarantees (C2PA hw attestation, known hash match)
  | "STRONG"          // Tier 2: Statistically robust, probabilistic but durable (cross-modal, frequency domain, watermarks)
  | "MODERATE"        // Tier 3: Useful, volatile under real-world conditions (face-swap detection, audio vocoder, metadata)
  | "WEAK";           // Tier 4: Aggregate-only, easily bypassed (text burstiness, domain reputation, community signals)

// ---------------------------------------------------------------------------
// 8. WEIGHT — Derived by pipeline (null at emission)

// ---------------------------------------------------------------------------
// 9. DEPENDENCIES — Array of evidence_id strings (empty = standalone)

// ---------------------------------------------------------------------------
// 10. RELATIONSHIPS type
// ---------------------------------------------------------------------------

interface EvidenceRelationship {
  /** The other evidence's ID. */
  readonly target_evidence_id: string;

  /** Nature of the relationship. */
  readonly relationship_type: RelationshipType;

  /** Analyzer-assessed strength of this relationship (0.0 = weak, 1.0 = definitive). */
  readonly strength: number;

  /** Human-readable explanation of the relationship. Max 280 chars. */
  readonly rationale: string;
}

type RelationshipType =
  | "CORRELATED_WITH"      // This evidence tends to co-occur with the target
  | "CONTRADICTS"           // This evidence disagrees with the target
  | "SUPERSEDES"            // This evidence makes the target obsolete (newer version, higher quality)
  | "DERIVED_FROM"          // This evidence was computed using the target as input
  | "SUPPORTS"              // This evidence corroborates (but is independent of) the target
  | "REFINES"               // This evidence adds precision to the target's signal
  ;

// ---------------------------------------------------------------------------
// 11. REPRODUCIBILITY type
// ---------------------------------------------------------------------------

type Reproducibility =
  | "DETERMINISTIC"        // Same analyzer + same content → always the same result (e.g., C2PA verification, hash match)
  | "HIGH_REPRODUCIBILITY"  // Same analyzer + same content → nearly identical result (± epsilon)
  | "LOW_REPRODUCIBILITY"   // Same analyzer + same content → may vary (e.g., ML model with runtime-dependent factors, random seeds)
  | "PROBABILISTIC"         // Inherently stochastic process. Multiple runs produce a distribution of outcomes.

// ---------------------------------------------------------------------------
// 12. EXPLAINABILITY type
// ---------------------------------------------------------------------------

interface Explanation {
  /**
   * Short explanation suitable for Quick Glance view.
   * Max 280 characters. Natural language. No technical metrics.
   * Example: "Valid C2PA manifest confirmed this image was captured by a Sony Alpha camera."
   */
  readonly short: string;

  /**
   * Detailed explanation suitable for Summary and Detailed views.
   * Multiple paragraphs. May include technical detail.
   * Example: "C2PA manifest verified with certificate chain: Sony Imaging CA → Sony Alpha 7R V (serial: ...). Assertion: captured 2026-07-15T10:23:00Z, no edits. Certificate valid, not revoked. Trust in signer: high (Sony's CA has zero recorded compromises)."
   */
  readonly detail: string;

  /**
   * Structured indicators for the UI layer to render visual cues.
   * Example: { "icon": "shield-check", "color": "green", "severity_icon": null }
   */
  readonly visual_indicators: VisualIndicator[];
}

interface VisualIndicator {
  readonly type: "icon" | "badge" | "severity_bar" | "confidence_ring";
  readonly value: string;   // Icon name, badge text, bar percentage, ring percentage
  readonly label: string;   // Accessible label (screen readers)
}

// ---------------------------------------------------------------------------
// 13. PRIVACY CLASSIFICATION type
// ---------------------------------------------------------------------------

/**
 * Governs where this evidence can be transmitted and how it can be cached.
 * See TRUST_ENGINE_SPEC Section 11.3 for privacy tier definitions.
 */
type PrivacyClassification =
  | "LOCAL_ONLY"              // Never leaves the device. C2PA verification, metadata extraction, local forensics.
  | "ANONYMIZED_QUERY"        // Network request without user content (domain hash lookup, cert revocation check).
  | "CONTENT_TRANSMITTED";    // Content sent to server. Requires explicit per-analysis opt-in. Reverse search, cloud deepfake detection.

// ---------------------------------------------------------------------------
// 14. EXPIRATION type
// ---------------------------------------------------------------------------

interface Expiration {
  /** The evidence becomes stale at this absolute timestamp (ISO 8601). */
  readonly expires_at: string;

  /** Or: duration from gathered_at until stale (ISO 8601 duration, e.g. "P7D" = 7 days). */
  readonly ttl: string | null;

  /** Why this evidence expires. For display to users (e.g. "Domain reputation data becomes stale after 7 days"). */
  readonly reason: string;

  /** Does the evidence automatically become WEIGHT=0 at expiration, or merely get a flag? */
  readonly behavior: ExpirationBehavior;
}

type ExpirationBehavior =
  | "ZERO_WEIGHT"      // Evidence contributes zero weight after expiration
  | "FLAGGED_ONLY"      // Evidence retains weight but is flagged as stale in UI
  | "CONTEXT_DEPENDENT"; // Some contexts (breaking news) zero the weight; others keep it flagged

// ---------------------------------------------------------------------------
// 15. CACHEABILITY type
// ---------------------------------------------------------------------------

interface Cacheability {
  /** Can this evidence result be cached? */
  readonly cacheable: boolean;

  /** If cacheable, how long is the cache valid? (ISO 8601 duration or null for no limit). */
  readonly cache_ttl: string | null;

  /** Must cached evidence be encrypted at rest? */
  readonly encryption_required: boolean;

  /** Cache key scope. Content-specific evidence is scoped to content_hash. Domain evidence is scoped to domain. */
  readonly cache_scope: CacheScope;

  /** Conditions that invalidate the cache (e.g., "analyzer_version_changed", "model_weights_updated"). */
  readonly invalidation_triggers: string[];
}

type CacheScope =
  | "CONTENT_SPECIFIC"              // Scoped to a specific content_reference hash/fragment
  | "DOMAIN_SPECIFIC"               // Scoped to a domain (e.g., domain reputation)
  | "ANALYZER_SESSION"              // Scoped to the analyzer's current session/lifetime in memory
  | "GLOBAL";                       // Not scoped (e.g., analyzer metadata, capabilities declaration)

// ---------------------------------------------------------------------------
// 16. VERIFICATION STATE type
// ---------------------------------------------------------------------------

type VerificationState =
  | "UNVERIFIED"            // Evidence emitted but not independently checked
  | "SELF_CERTIFIED"        // The analyzer self-certifies this result (e.g., C2PA verification is self-validating)
  | "PENDING_VERIFICATION"  // Verification is in progress (cross-check by another analyzer or pipeline)
  | "VERIFIED"              // Independently verified by another source/analyzer
  | "FAILED_VERIFICATION";  // Verification was attempted and this evidence did not pass

// ---------------------------------------------------------------------------
// 17. RUNTIME CONTEXT type
// ---------------------------------------------------------------------------

interface RuntimeContext {
  /** Browser family (for capability detection). */
  readonly browser: BrowserType;

  /** Browser version. */
  readonly browser_version: string;

  /** Operating system. */
  readonly os: string;

  /** Which capabilities were available at evidence gathering time. */
  readonly capabilities_available: BrowserCapability[];

  /** Which capabilities were needed by this analyzer but UNAVAILABLE. */
  readonly capabilities_missing: BrowserCapability[];

  /** Was the device online at evidence gathering time? */
  readonly online: boolean;

  /** The invocation model under which evidence was gathered. */
  readonly invocation_model: InvocationModel;
}

type BrowserType = "chrome" | "edge" | "firefox" | "safari" | "unknown";

type BrowserCapability =
  | "webgpu"
  | "offscreen_document"
  | "tab_capture"
  | "side_panel"
  | "storage_session"
  | "chrome_ai_api"
  | "sandboxed_page"
  | "canvas_pixel_access"
  | "service_worker"
  | "event_page";

type InvocationModel =
  | "on_demand"            // User clicked "Analyze this page"
  | "per_domain_auto"      // Automatic on user-allowlisted domains
  | "always_on_passive"    // Every page load (Phase 3+)
  | "context_menu"         // Right-click "Analyze this image"
  | "share_flow";          // Mobile share intent

// ---------------------------------------------------------------------------
// 18. ERROR type
// ---------------------------------------------------------------------------

interface EvidenceError {
  /** Classification of the error. */
  readonly error_class: ErrorClass;

  /** Machine-readable error code for programmatic handling. */
  readonly error_code: string;

  /** Human-readable error message (max 280 chars). */
  readonly message: string;

  /** Whether the pipeline should retry with the same input. */
  readonly retryable: boolean;

  /** Maximum retry attempts (null = no limit beyond pipeline default). */
  readonly max_retries: number | null;

  /** Suggested retry delay in milliseconds. */
  readonly retry_delay_ms: number;

  /** Stack or debug information (stripped in production, available in dev mode). */
  readonly debug_detail: string | null;
}

type ErrorClass =
  | "INTERNAL_ERROR"        // Analyzer crashed or threw an unhandled exception
  | "TIMEOUT"               // Analyzer exceeded its declared timeout budget
  | "UNAVAILABLE"           // Analyzer could not initialize (model not loaded, WASM failed, API key missing)
  | "UNSUPPORTED_CONTENT"   // Content type not processable by this analyzer (e.g., JPEG analyzer given PNG)
  | "INVALID_INPUT"         // Input was malformed, missing required data, or corrupted
  | "CAPABILITY_MISSING"    // Required browser capability was unavailable (tabCapture on Firefox, WebGPU on Safari)
  | "PERMISSION_DENIED"     // User denied or hasn't granted required permission
  | "CORS_BLOCKED"          // Cross-origin resource blocked by CORS policy
  | "NETWORK_ERROR"         // Network request failed (timeout, DNS error, server unreachable)
  | "CONTENT_NOT_LOADED"    // Content hasn't loaded yet (lazy image, SPA still rendering)
  | "QUOTA_EXCEEDED"        // Storage or memory quota exceeded
  | "PARTIAL_RESULT";       // Analyzer completed but with reduced confidence due to degraded input
```

### 1.4 Validation Rules

The following rules are enforced by the VALIDATION pipeline stage. Evidence objects failing any MUST rule are rejected before entering the Evidence Graph.

| # | Field | Rule | Severity |
|---|-------|------|----------|
| V1 | `evidence_id` | Must be valid UUID v7 (time-ordered). | **MUST** |
| V2 | `analyzer_id` | Must match `^[a-z0-9_-]+$` (kebab-case, no dots except version separator). | **MUST** |
| V3 | `analyzer_version` | Must be valid semver (`MAJOR.MINOR.PATCH`). | **MUST** |
| V4 | `gathered_at` | Must be valid ISO 8601 UTC, not future-dated, not before 2025-01-01. | **MUST** |
| V5 | `confidence.score` | Must be in range [0.0, 1.0]. | **MUST** |
| V6 | `confidence.score` | If < 0.5 and reliability_tier is GROUND_TRUTH, the evidence is rejected (ground truth evidence cannot be low-confidence). | **MUST** |
| V7 | `reliability_tier` | Must match the evidence_class according to the tier mapping. GROUND_TRUTH is only valid for PROVENANCE class. | **MUST** |
| V8 | `signal.signal_value` | `kind` field must match the actual runtime type of signal_value. | **MUST** |
| V9 | `signal.signal_type` | Must be one of the enumerated SignalType values (not free-form string). | **MUST** |
| V10 | `signal.signal_direction` | If SYNTHETIC, the analyzer must have evidence_class other than DERIVED (DERIVED can only be NEUTRAL or AUTHENTIC). | **MUST** |
| V11 | `content_reference.content_hash` | Must be 64 hex characters (SHA-256). | **MUST** |
| V12 | `explanation.short` | Must be ≤ 280 characters. | **MUST** |
| V13 | `explanation.short` | Must not contain technical metrics (percentages, model names, scores). | SHOULD |
| V14 | `weight` | Must be null at emission. Non-null weight is a pipeline-internal state and must not come from an analyzer. | **MUST** |
| V15 | `dependencies` | Every `evidence_id` in dependencies must be a valid UUID v7 format. Existence of the referenced evidence is checked at Evidence Graph insertion, not here. | **MUST** |
| V16 | `relationships` | `target_evidence_id` must be a valid UUID v7. `strength` must be in [0.0, 1.0]. | **MUST** |
| V17 | `privacy_classification` | If CONTENT_TRANSMITTED, `invocation_model` must NOT be `always_on_passive`. | **MUST** |
| V18 | `error` | If present, `signal.signal_type` must end with `_ERROR` or be a system-level signal type. | **MUST** |
| V19 | `runtime_context.capabilities_missing` | If non-empty, the evidence must carry reduced weight regardless of other factors. | SHOULD |
| V20 | `signal.signal_value` (SignalBinary) | Must not emit `true_meaning` that implies "AI-generated" for text content where `signal_type` is a text analysis type and `reliability_tier` is WEAK. | **MUST** |
| V21 | `signal.signal_value` (SignalDiscrete) | `category` must be from the controlled vocabulary defined per `signal_type`. | SHOULD |

## Part 2: Evidence Pipeline Architecture

### 2.1 Pipeline Overview

```
[DISCOVERY] → [EXTRACTION] → [NORMALIZATION] → [VALIDATION] → [EVIDENCE OBJECTS]
     ↓
[CONFIRMATION ASSIGNMENT] → [EVIDENCE GRAPH] → [FUSION ENGINE]
     ↓
[TRUST ENGINE] → [EXPLANATION GENERATOR] → [UI]
```

The pipeline is a **directed acyclic graph (DAG)** of stages. Evidence flows forward; feedback loops (re-analysis, retry) are handled by the pipeline orchestrator dispatching new pipeline instances, not by backward edges in the same instance.

### 2.2 Stage 1: DISCOVERY

| Attribute | Value |
|-----------|-------|
| **What enters** | `chrome.tabs.Tab` reference + page DOM snapshot (if content script) or nothing (if invoked from popup/service worker context). |
| **What exits** | `DiscoveryResult`: a catalog of discoverable content items on the page, each with type classification, locator, and priority score. |
| **Transformations** | 1. Identify main content region(s) using semantic landmarks (`<main>`, `<article>`, `role="main"`). Fallback: heuristics (largest text block, viewport center). 2. Classify page type (article, social media post, gallery, video, document, generic). 3. Enumerate content items: text blocks, images (`<img>`, `<picture>`, CSS `background-image`), videos (`<video>`), audio (`<audio>`), iframes. 4. Apply exclusion rules (navigation, ads, footers, cookie banners, icons < 50x50px, password fields — see Capability Assessment Section 2.3). 5. Detect social media platform and apply platform-specific container selectors. 6. Assign each content item a priority score based on viewport proximity, size, semantic role, and content type classification. 7. Generate a page fingerprint (structural hash for caching). |
| **Validation performed** | Page URL is valid and not a restricted page (`chrome://`, `about:`, `file://` without permission, Chrome Web Store). Extension has required permissions for this URL. |
| **What can be rejected** | Entire page: restricted URLs, no content detected (blank page, error page, pure navigation page). Specific content items: images below 50x50px, hidden elements (`display: none`, `visibility: hidden`, `aria-hidden="true"`), elements in excluded containers (ads, nav, footers), password/credit card fields, elements in closed shadow DOM (flagged as inaccessible). |
| **Synchronous or async?** | Synchronous phase (< 30ms): DOM landmark scan, page type detection, content enumeration. Async phase (deferred): social media platform detection, deep content enumeration, priority scoring refinement. |
| **Browser context** | `content_script` (primary). Falls back to `service_worker` + message passing if content script not yet injected. |
| **On failure** | If content script fails to inject or times out: return partial discovery (URL-level information only: domain, page type guessed from URL pattern). Flag assessment with `browser_capability_profile` indicating "content script unavailable." Discovery failure on a restricted page: return a single SYSTEM-class evidence object with signal_type `CONTENT_NOT_ACCESSIBLE`. |

### 2.3 Stage 2: EXTRACTION

| Attribute | Value |
|-----------|-------|
| **What enters** | `DiscoveryResult` (prioritized list of content items) + `PipelineContext` (invocation model, privacy prefs, timing budget). |
| **What exits** | `ExtractionResult`: raw content data bundles. Each bundle contains the bytes/text of a content item, its `ContentReference`, and extraction metadata. |
| **Transformations** | 1. For each content item, determine extraction strategy based on type, origin (same-origin vs. cross-origin), and privacy classification. 2. **Text:** Extract `innerText`/`textContent` from DOM element. Strip invisible characters, normalize whitespace. 3. **Same-origin images:** `fetch()` image bytes with CORS mode (`same-origin`). Decode dimensions via `createImageBitmap()` (no pixel-level access at this stage — that's for forensic analyzers). 4. **Cross-origin images:** Attempt `fetch()` with `mode: 'cors'`. If CORS headers present → extract bytes. If blocked → flag as `CORS_BLOCKED`, do not extract bytes. 5. **Video:** Extract `poster` frame (if same-origin) + `<video>` element metadata (duration, resolution, codec). Full frame extraction deferred to tabCapture (user-invoked). 6. **Audio:** Extract `<audio>` element metadata. Full audio extraction deferred to tabCapture. 7. **iframes:** For same-origin iframes, recursively discover and extract. For cross-origin iframes, flag as inaccessible. |
| **Validation performed** | Content bytes are non-empty. MIME type matches expected type (image/jpeg is actually a JPEG). Text is > 10 characters (below this, skip analysis). Image byte size is < 50 MB (configurable cap; above this, analyze metadata only). |
| **What can be rejected** | Empty content (0-byte images, whitespace-only text). Corrupt content (malformed image that fails to decode). Content exceeding size cap (flag as `TOO_LARGE`). Cross-origin images without CORS headers (flag as `CORS_BLOCKED`). Content in cross-origin iframes. Content in closed shadow DOM. |
| **Synchronous or async?** | Fully asynchronous. Runs in parallel across content items. Each item's extraction is independently cancelable. |
| **Browser context** | `content_script` for DOM access. Service worker dispatches extraction requests to content script. Large binary downloads (fetch of image bytes) may be delegated to sandbox/offscreen document to avoid blocking content script. |
| **On failure** | Per-item: item is removed from the analysis queue, flagged with `EXTRACTION_FAILED` error. The pipeline continues with remaining items. Extraction failure on ALL items: pipeline terminates with `NO_EXTRACTABLE_CONTENT` system evidence. |

### 2.4 Stage 3: NORMALIZATION

| Attribute | Value |
|-----------|-------|
| **What enters** | `ExtractionResult[]` — raw content data bundles (heterogeneous: text strings, ArrayBuffers, Blobs, element references). |
| **What exits** | `NormalizedContent[]` — uniform content representations ready for analyzer dispatch. Each has a canonical `ContentReference`, typed data payload, and context metadata. |
| **Transformations** | 1. Text: normalize to UTF-8, collapse whitespace, strip bidirectional control characters, compute text hash (SHA-256). Tokenize (word count, character count). 2. Images: detect actual format (magic bytes, not file extension). Convert to a uniform representation (ArrayBuffer with known MIME type). Compute content hash. Extract basic metadata (dimensions, format, byte size) into a standardized metadata block. 3. Video/Audio: extract container format, codec info, duration, resolution. Generate content hash from the initial bytes (for identification, not full-file hash for large files). 4. For all types: attach a `ContentReference` (generated from content hash + fragment locator). Attach source URL, DOM locator, discovery priority score. Compute a `normalized_content_id` (deterministic from content_hash). |
| **Validation performed** | Content hash is valid SHA-256. UTF-8 encoding is valid (no invalid byte sequences). Image format matches detected magic bytes (e.g., don't trust `.jpg` extension if magic bytes say PNG). Text encoding is detected and normalized correctly (respect `<meta charset>`, BOM). |
| **What can be rejected** | Content that fails hash computation (corrupted data). Invalid UTF-8 that cannot be recovered. Image bytes that are valid per MIME detection but fail to decode as that format. |
| **Synchronous or async?** | Asynchronous. Independent per content item. Parallelizable. |
| **Browser context** | `sandbox` (preferred — relaxed CSP for binary processing). Falls back to `service_worker` for lightweight normalization (text). `content_script` for DOM-dependent normalization (accessibility tree text). |
| **On failure** | Per-item: item flagged with `NORMALIZATION_FAILED` and excluded from further stages. All items fail: pipeline terminates with `NO_NORMALIZED_CONTENT` system evidence. |

### 2.5 Stage 4: VALIDATION

| Attribute | Value |
|-----------|-------|
| **What enters** | `NormalizedContent[]` + `PipelineContext` |
| **What exits** | `ValidatedContent[]` — the subset of normalized content that passed all validation gates, enriched with validation metadata. Content items that failed validation are recorded as `ValidationFailure` system evidence. |
| **Transformations** | 1. Apply content-type-specific validation rules. 2. Check privacy constraints: if `privacy_classification` is `CONTENT_TRANSMITTED` but user hasn't opted in, flag the content item for local-only analysis (exclude from cloud-routed analyzers). 3. Apply timing budget constraints: if the cumulative budget is exhausted, deprioritize remaining content items (they proceed only if time remains). 4. Apply capability constraints: if required browser capability is missing (e.g., tabCapture on Firefox), content items requiring it are flagged as `CAPABILITY_MISSING` but not rejected — they may still receive partial analysis from other analyzers. 5. Enforce the "Never Alone" rules from TRUST_ENGINE_SPEC Section 4: content types that are known to produce unreliable signals in isolation have those signals suppressed. |
| **Validation performed** | Content is not from a prohibited source (password fields, private browsing unless enabled, DRM content). Privacy mode is compatible with the planned analysis depth. Required permissions are held. Model versions are not deprecated. Analysis budget (time, memory, CPU) has not been exhausted. |
| **What can be rejected** | Content from prohibited sources. Content where user privacy settings explicitly forbid analysis. Content that exceeds the configured maximum count (e.g., analyze at most 20 images per page). |
| **Synchronous or async?** | Asynchronous but lightweight (< 5ms per item). Must not be a bottleneck. |
| **Browser context** | `service_worker` (orchestration context, has access to user preferences and capability state). |
| **On failure** | Validation stage failure (crash): pipeline aborts. All content items that haven't been validated yet are considered `VALIDATION_FAILED`. Previously validated items continue to next stages. |

### 2.6 Stage 5: EVIDENCE OBJECTS (Analyzer Dispatch & Collection)

| Attribute | Value |
|-----------|-------|
| **What enters** | `ValidatedContent[]` + `AnalyzerRegistry` (capability declarations of all registered analyzers) |
| **What exits** | `Evidence[]` — a collection of immutable Evidence objects (raw, no weight assigned yet). |
| **Transformations** | 1. **Routing:** For each `ValidatedContent`, query `AnalyzerRegistry` for compatible analyzers (matching content type, capability requirements, privacy tier). 2. **Prioritization:** Sort matched analyzers by: (a) reliability tier (GROUND_TRUTH first), (b) historical calibration accuracy, (c) execution cost (lightweight before heavyweight). 3. **Dispatch:** Invoke each analyzer in its required execution context. Content script analyzers run in content script. Heavy compute analyzers run in sandbox/offscreen. Network analyzers run in service worker (fetch). Cloud analyzers run via service worker → fetch to cloud. 4. **Parallel execution:** Independent analyzers run concurrently. Analyzers with dependencies wait for their dependency evidence IDs to be produced. 5. **Timeout enforcement:** Each analyzer has a declared timeout. Pipeline enforces it. On timeout, the analyzer produces an ERROR (TIMEOUT) evidence object rather than crashing. 6. **Result collection:** As analyzers complete, their raw output is wrapped in `Evidence` objects. The `evidence_id` is assigned by the pipeline (UUID v7). `weight` is set to null. `verification_state` is set to UNVERIFIED. `gathered_at` is set by the pipeline (when the Evidence object is created, not when the analyzer completed). 7. **Progressive emission:** Evidence objects are emitted progressively as analyzers complete (Tier 1 → Tier 2 → Tier 3). The Fusion Engine can begin processing before all analyzers finish. |
| **Validation performed** | Analyzer output conforms to the `Evidence` interface. All MUST validation rules from Section 1.4 are enforced here. Analyzers that produce malformed output are rejected and flagged with `ANALYZER_OUTPUT_INVALID`. |
| **What can be rejected** | Evidence objects that fail schema validation. Evidence objects from analyzers that are deprecated (analyzer_version older than minimum supported). Evidence objects from analyzers whose models fail signature verification (tampered models). |
| **Synchronous or async?** | Fully asynchronous. Multi-context (analyzers run in content script, service worker, sandbox, offscreen, cloud). Orchestrated from service worker. |
| **Browser context** | Orchestration: `service_worker`. Execution: whichever context the analyzer requires (`content_script`, `sandbox`, `offscreen`, `cloud`). |
| **On failure** | Per-analyzer failure: analyzer produces an ERROR evidence object (if it catches the error) or the pipeline generates a SYSTEM evidence object with `ANALYZER_CRASHED` signal_type. Analyzer failure does NOT abort other analyzers. All analyzers fail: pipeline produces at least one SYSTEM evidence object documenting the failure. The Fusion Engine may still produce a "Low Confidence / Insufficient Evidence" assessment. |

### 2.7 Stage 6: CONFIRMATION ASSIGNMENT

Note: Named "CONFIRMATION" not "CONFIDENCE" in the diagram — this stage assigns weights. The confidence is already set by the analyzer (field 6). This stage adjusts and derives.

| Attribute | Value |
|-----------|-------|
| **What enters** | `Evidence[]` (raw, weight=null) + `AnalyzerCalibrationRegistry` (historical calibration data per analyzer) + `PipelineContext` |
| **What exits** | `WeightedEvidence[]` — Evidence objects with `weight` assigned and `verification_state` updated where applicable. |
| **Transformations** | 1. **Base weight assignment:** Each evidence object's weight is initialized from: `weight_base = reliability_tier_weight_map[tier] × confidence.score`. The weight map is: GROUND_TRUTH → 1.0, STRONG → 0.6, MODERATE → 0.3, WEAK → 0.1. 2. **Calibration adjustment:** Weight is multiplied by the analyzer's historical calibration accuracy (measured on held-out test sets). An analyzer with 90% calibration accuracy gets 0.9× multiplier. An analyzer with 70% gets 0.7×. 3. **Decay adjustment:** Weight is multiplied by a decay factor based on analyzer age and model degradation rate. Analyzers using ML models decay over time; provenance analyzers (C2PA) do not. 4. **Capability penalty:** If `runtime_context.capabilities_missing` is non-empty, weight is reduced by a factor (0.5× per critical missing capability, configurable). 5. **Independence bonus:** Evidence that is truly independent from other evidence (different evidence_class, different methodology) receives a small weight bonus (+0.05, capped). 6. **Corroboration adjustment:** Evidence from classes that are never allowed to stand alone (see TRUST_ENGINE_SPEC Section 4.2) has its weight capped at 0.15 if no corroborating evidence from a higher tier exists. 7. **Self-certification:** Evidence with `reliability_tier = GROUND_TRUTH` and deterministic reproducibility has its `verification_state` set to `SELF_CERTIFIED` (no external verification needed). 8. **Normalization:** All weights are normalized to sum to 1.0 across all evidence for a given content reference (or left unnormalized if the Fusion Engine prefers raw weights). |
| **Validation performed** | All weights are in [0.0, 1.0]. Evidence with weight 0.0 is filtered out (does not enter Evidence Graph). The sum of weights for GROUND_TRUTH evidence is at least 0.4 of total weight (enforcing the "Tier 1 dominance" principle). |
| **What can be rejected** | Evidence where calibration data is missing AND the analyzer is uncalibrated (flag with `UNCALIBRATED_ANALYZER`, weight = 0.05 as a floor rather than rejecting). Evidence from deprecated analyzers (weight = 0.0, removed from pipeline). |
| **Synchronous or async?** | Synchronous (pure computation, no I/O). Runs in a single pass after all evidence from a given timing tier is collected. May run multiple times as progressive evidence arrives. |
| **Browser context** | `service_worker` (orchestration). Requires access to `AnalyzerCalibrationRegistry` (local data, synced periodically). |
| **On failure** | Failure to assign weights: all evidence enters the Evidence Graph with unweighted default weights (equal weighting across all evidence). Assessment is flagged with `WEIGHT_ASSIGNMENT_FAILED`. |

### 2.8 Stage 7: EVIDENCE GRAPH

| Attribute | Value |
|-----------|-------|
| **What enters** | `WeightedEvidence[]` |
| **What exits** | `EvidenceGraph` — a directed graph of evidence nodes and relationship edges, with traversal indices. |
| **Transformations** | 1. **Node insertion:** Each `WeightedEvidence` becomes a node in the graph. The node stores the evidence, its weight, and its content reference. 2. **Edge creation:** `EvidenceRelationship[]` entries become directed edges between nodes. Dependency entries also become edges (DEPENDS_ON edge type). 3. **Transitive closure (optional):** Compute transitive closure for relationship types that are transitive (SUPPORTS, CORRELATED_WITH, DERIVED_FROM). CONTRADICTS and SUPERSEDES are NOT transitive. 4. **Cycle detection:** The graph must remain acyclic. Cycles in dependency edges are an error (reject the evidence that creates the cycle). Cycles in relationship edges are allowed and flagged. 5. **Clustering:** Group evidence by content_reference (all evidence about the same content item forms a subgraph). 6. **Conflict detection:** Identify edges of type CONTRADICTS between nodes of similar weight. Generate CONFLICT_DETECTED meta-evidence for the fusion engine. 7. **Independence analysis:** Traverse the graph to identify evidence clusters with shared methodology (correlated evidence). Tag these for the fusion engine's independence cap. 8. **Topological sort:** Produce a topologically sorted traversal order (for fusion that processes evidence in dependency order). |
| **Validation performed** | No duplicate evidence_ids. No self-loops in dependencies. No cycles in dependency edges. All `target_evidence_id` values in relationships reference nodes that exist in the graph (orphan references are removed and logged). |
| **What can be rejected** | Evidence that would create a dependency cycle. Evidence whose `dependencies` reference non-existent evidence IDs (the dependency is removed, and the evidence is flagged with `UNRESOLVED_DEPENDENCY`; weight is reduced). |
| **Synchronous or async?** | Synchronous (graph construction). As the graph grows with progressive evidence, incremental updates are performed. |
| **Browser context** | `service_worker` (in-memory graph). Graph is serialized to `chrome.storage.session` for service worker persistence across wake cycles. |
| **On failure** | Graph construction failure: evidence is stored in a flat list instead of a graph. Fusion Engine falls back to flat evidence combination (treating all evidence as independent). |

### 2.9 Stage 8: FUSION ENGINE

| Attribute | Value |
|-----------|-------|
| **What enters** | `EvidenceGraph` + `FusionContext` (prior base rates, confidence thresholds, user sensitivity preferences) |
| **What exits** | `FusionResult` — a posterior confidence distribution over content authenticity categories, with credible intervals, conflict flags, and uncertainty decomposition. |
| **Transformations** | 1. **Prior selection:** Choose the Bayesian prior based on content type classification (from discovery stage). 2. **Signal independence enforcement:** Cap the contribution from any single evidence class at 60% of total weight. Cap any single signal at 40% of total weight (per TRUST_ENGINE_SPEC Section 5.4). 3. **Bayesian updating:** For each evidence node in topological order, compute likelihood ratio and update the posterior. Evidence is converted to a likelihood ratio via its calibrated signal value and direction. 4. **Safety override rules:** Apply hard floors. Valid hardware-attested C2PA → floor on authenticity confidence. Known synthetic signature hash match → floor on AI-generation confidence. 5. **Conflict integration:** Conflicting evidence is NOT smoothed. The fusion result includes a `conflicts` array listing conflicting evidence pairs, their respective signals, and suggested resolution steps. 6. **Credible interval computation:** Compute the 90% credible interval from the posterior distribution. 7. **Discrete confidence level mapping:** Map the posterior probability to a discrete confidence level (0-5, per TRUST_ENGINE_SPEC Section 6.2). |
| **Validation performed** | Posteriors are in [0.0, 1.0]. Credible intervals are well-formed (lower < upper). At least one evidence node contributed (if zero, result is "Insufficient Evidence"). The "Never Alone" rules are enforced (single-signal assessments capped at "Low Confidence"). |
| **What can be rejected** | Nothing is "rejected" at this stage. The fusion engine always produces a result, even if that result is "Insufficient Evidence." |
| **Synchronous or async?** | Synchronous (pure computation). Runs as a batch when all evidence from a timing tier is available. Re-runs incrementally as new evidence arrives. |
| **Browser context** | `service_worker` or `sandbox` (computation is lightweight enough for SW, but may be moved to sandbox if complex graph traversal is needed). |
| **On failure** | Fusion engine crash: produce a `FusionResult` with confidence level 0 ("Insufficient Evidence"), error flag set, and the raw evidence list attached for debugging. |

### 2.10 Stage 9: TRUST ENGINE

| Attribute | Value |
|-----------|-------|
| **What enters** | `FusionResult` + `WeightedEvidence[]` (original evidence) + `PipelineContext` |
| **What exits** | `TrustAssessment` — the canonical output of the entire pipeline. A signed, versioned, self-contained assessment that is the single source of truth for UI and export. |
| **Transformations** | 1. **Assessment assembly:** Combine fusion result with pipeline metadata (pipeline version, timestamp, browser capability profile, invocation model, privacy mode). 2. **Completeness scoring:** Compute coverage completeness (% of applicable evidence sources that returned results). 3. **Recency tagging:** Tag assessment with recency metadata for time-sensitive content types. 4. **Privacy tier annotation:** Annotate with which privacy tier was used (affects confidence ceiling). 5. **Cryptographic signing:** Sign the assessment with the extension's signing key (for export verification). 6. **Version binding:** Bind the assessment to specific model/analyzer versions for reproducibility. 7. **Chain of custody:** Append a chain-of-custody record: analysis timestamps, model versions, platform info. |
| **Validation performed** | Assessment is internally consistent (evidence count matches graph, signal directions align with confidence level). Assessment is not a binary verdict (must not contain "This is AI-generated" or "Verified authentic" — see TRUST_ENGINE_SPEC Section 6.3). Confidence level is discrete (0-5), not a continuous percentage. |
| **What can be rejected** | Assessments that would output prohibited language (binary verdicts, certainty claims). Assessments where the system detects it may be compromised (failed signature checks on models). In this case: FAIL CLOSED — produce an assessment stating "Analysis unavailable. Please reinstall or update Sentinel." |
| **Synchronous or async?** | Synchronous. The final assembly step before handoff to explanation generator. |
| **Browser context** | `service_worker`. |
| **On failure** | Fail closed: produce a minimal `TrustAssessment` with confidence level 0 and an error message directing the user to reinstall/update. |

### 2.11 Stage 10: EXPLANATION GENERATOR

| Attribute | Value |
|-----------|-------|
| **What enters** | `TrustAssessment` + `WeightedEvidence[]` |
| **What exits** | `ExplainableAssessment` — the assessment enriched with three-tier explainability output (Quick Glance, Summary, Detailed Report). |
| **Transformations** | 1. **Quick Glance generation (1-3 seconds readability):** Confidence level badge, direction indicator, top 1-2 strongest evidence points in natural language, timestamp, privacy mode indicator. 2. **Summary View generation (10-30 seconds readability):** Per-signal breakdown (every evidence signal listed with individual finding and tier), signal agreement summary, missing signals listed with reason, key findings in natural language paragraphs, actionable recommendations. 3. **Detailed Report generation (2-5 minutes readability):** Full evidence chain, methodology notes, raw per-signal likelihood ratios, chain of custody, exportable/signed format. 4. **Conflict narrative generation:** For each conflict in the fusion result, generate a natural-language explanation of what the conflict means and what the user should do. 5. **Evidence visual category assignment:** Assign each evidence item to a visual category (Provenance, Detection, Reputation, Corroborative, Missing, Inconclusive) for consistent UI rendering. |
| **Validation performed** | Output contains no prohibited language (see TRUST_ENGINE_SPEC Section 8.2). Quick Glance is ≤ 280 characters total. Detailed Report is structured and complete (all evidence referenced). |
| **What can be rejected** | Nothing. The explanation generator always produces output, even if it's a terse "Analysis could not be completed." |
| **Synchronous or async?** | Asynchronous (template rendering and natural-language generation). Runs in parallel with UI rendering. |
| **Browser context** | `service_worker` (template-based generation) or `sandbox` (if using small NLG model for richer explanations). |
| **On failure** | Falls back to a structured-only output (raw evidence list with labels, no natural language narrative). |

### 2.12 Stage 11: UI

| Attribute | Value |
|-----------|-------|
| **What enters** | `ExplainableAssessment` |
| **What exits** | Rendered UI in popup, side panel, or content script overlay. |
| **Transformations** | Renders the three-tier explainability view. Progressive disclosure (Quick Glance → tap/click for Summary → tap/click for Detailed). Updates live as progressive evidence arrives. |
| **Validation performed** | UI renders without layout issues. All interactive elements have accessible labels. Confidence level rendering uses discrete levels, not raw percentages. |
| **What can be rejected** | N/A (UI stage, not filtering stage). |
| **Synchronous or async?** | Async rendering. Popup/side panel: renders in their respective DOM contexts. Content script overlay: renders in page DOM. |
| **Browser context** | `popup` / `side_panel` / `content_script` (overlay). |
| **On failure** | UI fails gracefully: show error state with "Analysis results unavailable" and a retry button. |

### 2.13 Cross-Cutting Concerns

#### 2.13.1 Progressive Analysis Flow

The pipeline runs in timing tiers (per Capability Assessment Section 4.3):

```
Tier 1 (< 500ms):  DISCOVERY → EXTRACTION (text) → NORMALIZATION → VALIDATION
                    → EVIDENCE OBJECTS (fast analyzers: EXIF, domain cache, text style)
                    → CONFIRMATION ASSIGNMENT → EVIDENCE GRAPH → FUSION ENGINE
                    → TRUST ENGINE → EXPLANATION GENERATOR → UI (Preliminary)

Tier 2 (1-5s):     (same pipeline stages, now with C2PA, text perplexity, metadata analysis)
                    → UI updates with Refined assessment

Tier 3 (user-invoked): (image forensics, video analysis, audio analysis, cross-modal)
                    → UI updates with Deep assessment
```

The UI receives incremental updates: `AssessmentUpdate { assessment_version: number; delta: Partial<ExplainableAssessment>; is_final: boolean }`.

#### 2.13.2 Pipeline Orchestration

The pipeline is orchestrated by a `PipelineOrchestrator` running in the service worker. It manages:
- Pipeline instance lifecycle (one instance per user invocation)
- Stage sequencing and parallelization
- Timeout enforcement per stage and per analyzer
- Context lifetime management (keeping service worker alive via `chrome.runtime.connect`, opening/terminating sandbox pages and offscreen documents)
- Progressive result emission to UI
- Cancellation (user navigates away, tab closes)
- Retry logic (exponential backoff for network-dependent analyzers)

#### 2.13.3 Context Mapping

| Evidence Class | Default Execution Context | Fallback Context |
|---------------|--------------------------|-----------------|
| PROVENANCE | sandbox (c2pa-rs WASM) | offscreen (Chrome/Edge), service_worker (lightweight only) |
| FORENSIC | sandbox (ONNX models) | offscreen |
| WATERMARK | sandbox or service_worker (algorithm-dependent) | |
| STATISTICAL | sandbox (perplexity models) or service_worker (pure JS stats) | |
| REPUTATION | service_worker (fetch to cloud or local cache) | |
| CROSS_MODAL | sandbox (CLIP-ViT, ONNX) | offscreen |
| REFERENCE | service_worker (fetch) or cloud (service_worker → external API) | |
| DERIVED | service_worker (pure computation) | |
| SYSTEM | service_worker | |

#### 2.13.4 Pipeline State Machine

```
[IDLE] → [DISCOVERING] → [EXTRACTING] → [NORMALIZING] → [VALIDATING]
    → [ANALYZING] → [ASSIGNING_WEIGHTS] → [BUILDING_GRAPH] → [FUSING]
    → [ASSEMBLING_ASSESSMENT] → [GENERATING_EXPLANATION] → [RENDERING]
    → [COMPLETE]

Any state → [CANCELLED] (user navigates away, tab closes, timeout)
Any state → [ERROR] (unrecoverable failure)
[COMPLETE] → [UPDATING] (new evidence from later timing tier) → [COMPLETE]
```

## Part 3: Interfaces & Contracts

### 3.1 Analyzer Interface

Every analyzer plugin must implement this interface. The pipeline calls these methods in the declared execution context.

```typescript
interface Analyzer {
  // ---------------------------------------------------------------------------
  // Identity & Capability Declaration (called at registration time, not per-analysis)
  // ---------------------------------------------------------------------------

  /** Unique identifier. kebab-case, lower-case alphanumeric + hyphens. */
  readonly analyzer_id: string;

  /** Semantic version. */
  readonly analyzer_version: string;

  /** Human-readable display name (e.g. "C2PA Manifest Verifier"). */
  readonly display_name: string;

  /**
   * Capability declaration: what this analyzer can process, what it needs,
   * and what it produces. This is used by the pipeline for routing.
   */
  readonly capability: AnalyzerCapability;

  // ---------------------------------------------------------------------------
  // Lifecycle (called by pipeline at appropriate times)
  // ---------------------------------------------------------------------------

  /**
   * Initialize the analyzer. Called once when the analyzer is first needed.
   * May load WASM models, download assets, warm up execution context.
   * Must be idempotent. Must not throw — return AnalyzerStatus instead.
   *
   * @returns Status indicating ready, initializing (async), or failed.
   */
  initialize(): Promise<AnalyzerStatus>;

  /**
   * Analyze a single normalized content item and produce evidence.
   * Called once per content item this analyzer is routed to.
   * MUST NOT throw. All errors must be returned as Evidence with appropriate error fields.
   * MUST respect the timeout declared in `capability.execution_budget.timeout_ms`.
   *
   * @param content - The normalized content to analyze.
   * @param context - Pipeline context (invocation model, privacy prefs, timing tier).
   * @param dependencies - Evidence objects this analyzer declared dependencies on (via capability.dependencies).
   *                       Empty array if no dependencies.
   * @returns An Evidence object. Never null, never throws.
   */

    content: NormalizedContent,
    context: PipelineContext,
    dependencies: Evidence[]
  ): Promise<Evidence>;

  /**

   * (pipeline complete, context termination, extension shutdown).
   * Must be idempotent. Must not throw.
   */
  terminate(): Promise<void>;

  /**
   * Validate that this analyzer can process the given content type.
   * Lightweight check used for routing. Should not load models.
   *
   * @returns true if this analyzer can handle this content. Returns false for unsupported types.
   */
  canAnalyze(content: NormalizedContent): boolean;

  // ---------------------------------------------------------------------------
  // Calibration (for weight assignment)
  // ---------------------------------------------------------------------------

  /**
   * The analyzer's self-reported calibration data.
   * Updated periodically as the analyzer is recalibrated against ground truth.
   * The pipeline uses this for weight adjustment in CONFIRMATION ASSIGNMENT stage.
   */
  readonly calibration: AnalyzerCalibration;
}
```

### 3.4 EvidenceGraph Interface

Nodes are evidence objects; edges are relationships. The graph supports traversal, clustering, and conflict detection.

```typescript
interface EvidenceGraph {
  // ---------------------------------------------------------------------------
  // Structure
  // ---------------------------------------------------------------------------

  /** All evidence nodes in the graph. */
  readonly nodes: ReadonlyMap<string, Evidence>;

  /** All relationship edges. */
  readonly edges: ReadonlySet<GraphEdge>;

  /** Subgraphs keyed by content_reference. */
  readonly subgraphs: ReadonlyMap<string, EvidenceSubgraph>;

  // ---------------------------------------------------------------------------
  // Queries
  // ---------------------------------------------------------------------------

  /**
   * Resolve the effective evidence for a content reference, considering
   * SUPERSEDES relationships (newer evidence replaces older), dependencies
   * (DERIVED_FROM), and conflicts (CONTRADICTS).
   */
  resolveEffectiveEvidence(content_reference: ContentReference): Evidence[];

  /**
   * Get all evidence transitively dependent on the given evidence_id.
   * Follows DERIVED_FROM edges in reverse.
   */
  getDependents(evidence_id: string): Evidence[];

  /**
   * Get all evidence that the given evidence depends on (direct + transitive).
   */
  getDependencyChain(evidence_id: string): Evidence[];

  /**
   * Find all conflicting evidence pairs in the graph.
   * A conflict exists when two evidence nodes have relationship CONTRADICTS
   * OR when two evidence nodes have weight > threshold and signal_direction
   * are opposed (one AUTHENTIC, one SYNTHETIC) even without an explicit edge.
   */
  findConflicts(weight_threshold: number): ConflictPair[];

  /**
   * Compute independence clusters: groups of evidence that share methodology
   * and are therefore correlated. The fusion engine uses this to cap per-class weight.
   */
  computeIndependenceClusters(): IndependenceCluster[];

  /**
   * Topological sort respecting dependency edges. Used by fusion engine
   * to process evidence in dependency order.
   */
  topologicalSort(): Evidence[];

  /**
   * Get all evidence that is currently "active" (not superseded, not expired,
   * verification state is not FAILED_VERIFICATION).
   */
  getActiveEvidence(): Evidence[];

  /**
   * For a given content reference, what percentage of applicable evidence
   * classes are represented in the graph?
   */
  computeCoverage(content_reference: ContentReference): CoverageReport;

  // ---------------------------------------------------------------------------
  // Metadata
  // ---------------------------------------------------------------------------

  /** When the graph was created. */
  readonly created_at: string;

  /** When the graph was last modified (new evidence added). */
  readonly last_modified_at: string;

  /** Total node count. */
  readonly node_count: number;

  /** Total edge count. */
  readonly edge_count: number;
}

interface GraphEdge {
  readonly source_id: string;
  readonly target_id: string;
  readonly relationship: EvidenceRelationship;
}

interface EvidenceSubgraph {
  readonly content_reference: ContentReference;
  readonly nodes: Evidence[];
  readonly edges: GraphEdge[];
}

  readonly evidence_a: Evidence;
  readonly evidence_b: Evidence;
  readonly conflict_type: ConflictTier;
  readonly resolution_suggestion: string;
}

 * Conflict severity tiers (from TRUST_ENGINE_SPEC Section 7.2).
 */

  | "CRITICAL"    // Tier 1 vs. Tier 1
  | "HIGH"        // Tier 1 vs. Tier 2
  | "MODERATE"    // Tier 2 vs. Tier 2
  | "LOW";        // Tier 3/4 vs. anything higher

interface IndependenceCluster {
  readonly cluster_id: string;
  readonly evidence_class: EvidenceClass;
  readonly evidence_ids: string[];
  readonly correlation_strength: number;  // 0.0 = fully independent, 1.0 = fully dependent
  readonly rationale: string;
}
```

## Appendix A: Controlled Vocabularies

### A.1 Reliability Tier → Base Weight Map

| Reliability Tier | Base Weight | Applies To |
|-----------------|-------------|------------|
| GROUND_TRUTH | 1.0 | Cryptographic provenance, hardware attestation, known hash match |
| STRONG | 0.6 | Cross-modal consistency, frequency domain, watermark detection |
| MODERATE | 0.3 | Face-swap detection, audio vocoder, EXIF/IPTC metadata, reverse search |
| WEAK | 0.1 | Text burstiness, domain reputation, community signals, absence of provenance |

### A.2 Evidence Class → Reliability Tier Mapping (Validation Rule V7)

| Evidence Class | Valid Reliability Tiers |
|---------------|------------------------|
| PROVENANCE | GROUND_TRUTH only |
| FORENSIC | STRONG or MODERATE |
| WATERMARK | STRONG or MODERATE |
| STATISTICAL | MODERATE or WEAK |
| REPUTATION | WEAK |
| CROSS_MODAL | STRONG |
| REFERENCE | MODERATE or WEAK |
| DERIVED | MODERATE (computed by pipeline, not analyzer) |
| SYSTEM | WEAK (informational only, zero weight at fusion) |

### A.3 Conflict Tier → Weight Threshold → Behavior

| Conflict Tier | Weight Threshold | Behavior |
|--------------|-----------------|----------|
| CRITICAL | Both > 0.5 | Confidence capped at level 2 (Uncertain). Both claims displayed. |
| HIGH | Higher-tier > 0.5, lower-tier > 0.6 | Higher-tier dominates but conflict surfaced. |
| MODERATE | Both > 0.3 | Noted as disagreement. Weighted average used. |
| LOW | Either < 0.3 | Lower-tier signal noted but does not create a conflict. |

### A.4 "Never Alone" Rule Enforcement Summary

| Evidence Type | Minimum Corroboration |
|---------------|----------------------|
| Text burstiness/perplexity | At least 1 signal from STRONG or GROUND_TRUTH |
| Face-swap detection | At least 1 additional signal from any tier |
| Audio vocoder artifacts | At least 1 PROVENANCE or FORENSIC signal |
| IPTC/EXIF metadata alone | At least 1 FORENSIC or PROVENANCE signal |
| Reverse search alone | At least 1 FORENSIC or METADATA signal |
| Domain reputation | At least 2 signals from STRONG or above |
| Community signals | At least 3 signals from STRONG or above |
| Any single signal | Capped at confidence level 2 (Uncertain) |

### A.5 Evidence Class Contribution Caps

| Cap | Value | Enforcement Point |
|-----|-------|-------------------|
| Single signal max weight | 40% of total fusion weight | Fusion Engine |
| Single evidence class max weight | 60% of total fusion weight | Fusion Engine |
| Minimum evidence classes for High Confidence (level 4) | 2 distinct classes | Fusion Engine |
| Minimum evidence classes for Very High Confidence (level 5) | 3 distinct classes including at least 1 GROUND_TRUTH | Fusion Engine |

## Appendix C: Serialization & Cross-Context Transfer

Evidence objects must survive the following boundaries:

| Boundary | Method | Constraints |
|----------|--------|-------------|
| Content Script → Service Worker | `chrome.runtime.sendMessage()` | JSON-serializable. ArrayBuffers must be base64-encoded or transferred via `chrome.runtime.connect()` port with binary messages. |
| Service Worker → Sandbox Page | `postMessage()` to sandbox iframe | Structured clone algorithm. Supports ArrayBuffer, Blob, ImageBitmap transfer. |
| Service Worker → Offscreen Document | `chrome.runtime.sendMessage()` to offscreen document | Same as content script boundary. |
| Service Worker → Popup/Side Panel | `chrome.runtime.sendMessage()` | JSON-serializable. Popup/side panel are same extension process, so structured cloning is more permissive. |
| Any context → chrome.storage.session | `chrome.storage.session.set()` | Values must be JSON-serializable. ArrayBuffers are NOT supported in storage.session (Chrome limitation). Store as base64 or reference by ID. |
| Export (PDF/JSON) | `JSON.stringify()` + signature | Full JSON serialization. Binary data in evidence (ArrayBuffer) may be excluded from export (metadata only). |

For binary-heavy evidence (image forensics pixel data), the Evidence object stores a **reference** (evidence_id + storage location) rather than the raw data. The raw data is held in memory within the execution context and discarded after fusion.
